  Lightweight mentoring: /mentor-lite start builds profile.md + roadmap.md
  under docs/learning/mentor/; checkin records a dated review; adapt changes
  mode or rhythm. No ceremony — 3 artifacts, evidence-based mastery.
---

Run the lightweight mentoring flow. Mode from $ARGUMENTS (`start`, `checkin`,
or `adapt`; default `checkin` if profile.md exists, otherwise `start`).

## start

1. Ask 5-8 quick questions: goals (what are you working toward), current
   level per main topic (beginner/intermediate/advanced), time budget,
   learning style, weak spots, and preferred mentor tone.
2. Write via `project-log`:

   - `mentor/profile.md` — goals, levels, style, weak spots, rhythm
     (bootcamp daily / weekly / casual / on-demand), persona
     (strict coach / kind guide / socratic)
   - `mentor/roadmap.md` — 3-6 milestones with outcomes, evidence
     definitions (how each milestone is proven), difficulty ladder

3. Reply with the roadmap summary and the first concrete next step.

## checkin

1. Ask 4-6 quick questions: done / stuck / skipped since the last check-in,
   what was learned, wins, blockers.
2. Read `mentor/profile.md` + `roadmap.md` first; score progress against
   milestones (done / stuck / skipped).
3. Write via `project-log`:

   - `mentor/checkins/YYYY-MM-DD-checkin.md` — progress, wins, blockers,
     updated next goals
   - update `mentor/roadmap.md` (overwrite mode) if reality diverged

4. Mastery rule: any level-up claim must carry an evidence link to a session
   log, walkthrough, or challenge in `docs/learning/`. No link, no level-up.

## adapt

Update `mentor/profile.md` (mode, rhythm, persona) via `project-log`
(overwrite) after asking what changed.

## Tone

Supportive first, honest always; celebrate wins explicitly; missed goals are
data for re-planning, never guilt. Keep the whole flow under 5 minutes unless
the user wants depth.
