# Skill: mentor-graduation

## Purpose

A mentor's job is to make itself less needed. Graduation is the proof: a
clean final assessment, an honest exit interview, and an archive the learner
(and the mentor) can return to.

---

## When to Use

Use this skill when:

- Roadmap goals are reached (milestones done, challenges completed).
- The learner says "أنا كفاية كده" / "I think I'm done" / "let's close this".
- A planned period (3 months, semester) ends.
- Alumni return: the learner comes back after graduation (load the archive).

---

## Step-by-Step Workflow

1. **Confirm the trigger** — ask: is this goal-reached, life-changed, or
   discouraged? (Discouraged → do NOT graduate; run `mentor-motivation` +
   re-scope instead. Graduation must be earned or chosen, not an escape.)
2. **Final assessment**:
   - Mastery snapshot: full table from `mastery.md` (topic → final level).
   - Roadmap status: milestones done / dropped (with reasons).
   - Challenges: completed count; top 3 prouds.
3. **Exit interview** (5 questions):
   - What worked in our sessions?
   - What didn't?
   - What should the mentor change for future learners? (self-improvement)
   - What's the one thing you still want to learn on your own?
   - Would you recommend this mode? What would you change?
4. **Write `mentor/graduation.md`** (via `learning-log`):
   - The snapshot, the answers, and a **"without-me plan"**: self-directed
     next steps (topics, projects, resources), spaced review schedule for the
     next 3 months, and when to return (condition-based: "come back when you
     start X").
5. **Cross-project rollup** — `memory-log` →
   `memory/mentor/rollup.md`: append a summary (project, dates, top skills
   mastered, notable wins) so future mentor sessions in ANY repo know this
   learner's history.
6. **Archive** — mark `profile.md` / `roadmap.md` rows "archived <date>"
   (keep files; history stays). Update `challenges.md` statuses to done.
7. **Close well** — a short, sincere closing message: what they proved
   (evidence, not flattery) and what comes next.

### Alumni return (later)

- Load `graduation.md` + `memory/mentor/rollup.md`.
- Greet: "Welcome back — when we closed, you were Proficient on X and aiming
  for Y. What brings you back?"
- Re-open only what they need (light re-intake), then resume with the
  rollup as the starting context.

---

## Notes

- Graduation is not deletion: everything stays in `docs/learning/mentor/`.
- The rollup is the multi-project memory bridge — without it, each repo's
  mentor starts blind.
- If goals changed mid-way (not reached but no longer relevant), use
  `/mentor-reaim` instead of graduating or guilt-tripping.
